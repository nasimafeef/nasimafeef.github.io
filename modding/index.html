Modding

Add new cars to drive and new cars for the traffic, with vehicle packs.

Install a pack Make your own Get the Mod Kit Rules

A vehicle pack is a small add-on folder you copy onto your phone. The game loads it when it starts; nothing in the installed game changes, and you can remove it any time.

  • Drivable cars appear in the garage after the built-in ones.
  • Traffic cars are mixed into the traffic on the roads.
  • Packs are made on a Windows PC with the free Unreal Engine 5.8 and our Mod Kit.

Install a vehicle pack

  1. Get the pack's folder (for example RaviCars) from its author. It contains a .uplugin file and a Content folder.
  2. Connect your phone to a computer, or use a file manager app, and copy the whole folder to: 
    Android/data/com.evastudios.vehiclesimulator/files/UnrealGame/VehicleSimulator/VehicleSimulator/Plugins/GameFeatures/
    Create the Plugins/GameFeatures folders if they don't exist yet.
  3. Restart the game.
  4. On the main menu tap Mods. The pack should say Loaded and list its cars. If it says Could not load, the reason is shown underneath.

To remove a pack, delete its folder and restart the game.

Packs are made for one version of the game. After a game update, a pack only loads once its author rebuilds it for the new version. In multiplayer, everyone needs the same packs: the host refuses cars it doesn't have.

Make your own

This walks you through making a pack from nothing to driving your own car model on your phone: one you made (for example in Blender) or one whose licence lets you share it. The examples use a pack called RaviCars and a car called RaviCar; use your own names. It takes about an hour the first time, most of it waiting for downloads.

1. What you need

  • A Windows PC with about 60 GB free (Unreal Engine is big).
  • Unreal Engine 5.8: free, from the Epic Games Launcher (step 2).
  • The Mod Kit for the version of the game on your phone.
  • An Android phone with the game, and a USB cable.
  • No coding. You only place things and fill in settings.

2. Install Unreal Engine 5.8

  1. Install the Epic Games Launcher from epicgames.com and sign in (a free Epic account).
  2. In the launcher: Unreal Engine → Library → the + next to Engine Versions. Choose version 5.8.
  3. Before installing, click the arrow next to Install → Options, and tick Android under Target Platforms. Without it the kit can't build for phones. If you already installed 5.8 without it: Library → the arrow next to Launch → Options → tick Android → Apply.
  4. Click Install. It's a large download; carry on reading while it runs.

Use exactly 5.8. The kit's game plugins are built for it; any other version refuses to open the kit.

3. Unzip the Mod Kit

  1. Download the Mod Kit for your game version.
  2. Unzip it somewhere with a short path, such as C:\Mods\. You get a folder called VehicleSimulator. Don't rename it: the game finds pack files by that name.
  3. Open MODKIT_RELEASE.txt inside. It says which game release the kit is for. A pack only works on that release; when the game updates, download the new kit and rebuild your pack (step 11).

The kit contains the parts of the game a car plugs into, the tools, and the full written guide (README.md). It contains no car models and no sounds: cars are silent while you work in Unreal, and use the game's engine, skid and crash sounds on your phone.

4. Create your pack

  1. Pick a pack name: one word, letters and digits only, for example RaviCars. It becomes the start of every id in your pack, and can't change later.
  2. Make sure Unreal is closed.
  3. Open the VehicleSimulator folder in File Explorer, click the address bar, type powershell and press Enter. A PowerShell window opens in that folder.
  4. Run this, with your own pack name, display name and author: 
    powershell -ExecutionPolicy Bypass -File Tools/Mods/New-VehiclePack.ps1 -Pack RaviCars -FriendlyName "Ravi's Cars" -Author "Ravi"
    It creates Plugins/GameFeatures/RaviCars and switches the pack on in Unreal.

5. Set up the pack in Unreal

  1. Double-click VehicleSimulator.uproject. The first start takes several minutes while Unreal prepares shaders. If it asks which engine to use, choose 5.8.
  2. At the bottom, open the Content Browser (Ctrl+Space). Click its Settings (⚙) and tick Show Plugin Content. A folder RaviCars Content appears in the list on the left.
  3. Right-click inside that folder → Miscellaneous → Data Asset → pick GameFeatureData → name it exactly like your pack: RaviCars.
  4. Double-click it. Under Primary Asset Types to Scan, click + twice and fill in:
    Primary Asset TypeAsset Base ClassDirectoriesRules → Cook Rule
    EvaVehicleEvaVehicleDefinition/RaviCars/VehiclesAlways Cook
    EvaTrafficVehicleEvaTrafficVehicleDefinition/RaviCars/VehiclesAlways Cook
    Type the directory with your own pack name. These tell the game where to find your cars.
  5. In the pack folder, right-click → New Folder → Vehicles.
  6. Save All (Ctrl+Shift+S), then close and reopen Unreal. This is the only restart you need. After it, the Output Log (Window → Output Log) shows Game feature 'RaviCars' … Ending state: Active.

Everything goes inside your pack's folder. Models, materials, textures and Blueprints all live under RaviCars. Anything your pack uses from outside it (other than the game parts the kit provides) makes the build fail.

6. Prepare and import your model

Your model must be yours to share: made by you, or with a licence that allows it. No models ripped from other games.

What the model needs (set this up in your 3D program before exporting):

  • A skeletal mesh (an armature/rig): a root bone for the body and one bone per wheel, placed at the wheel's centre, with each wheel's geometry skinned 100% to its bone. Short names like FL, FR, RL, RR are fine.
  • Optional: a bone named exactly SteeringWheel for the steering wheel, with its geometry skinned to it; the game turns it as you steer (step 12). Other moving parts (doors, wipers) also need their own bones.
  • Facing +X (forward), Z up, in centimetres, with the pivot at ground level under the middle of the car.
  • The root bone must have zero rotation. The car's physics takes "forward" from the root bone, not from how the mesh looks. From Blender, export FBX with Armature → Primary Bone Axis: X and Secondary Bone Axis: -Y (or Y), or rotate the root bone so it has no rotation.
  • Phone-friendly: under 30,000 vertices for a drivable car (10,000 for a traffic-only car), textures 2048 px or smaller.

Import it:

  1. In your pack folder, right-click → New Folder → Meshes, and open it.
  2. Drag your .fbx file into the Content Browser. In the import dialog tick Skeletal Mesh and Create Physics Asset, then Import. You get the mesh, a …_Skeleton, a …_PhysicsAsset, and its materials and textures.
  3. Check the root bone. Open the …_Skeleton, click the root bone in the Skeleton Tree: its Rotation must read 0, 0, 0. If it says -90 or 90, the car will spin in place when you accelerate; re-export from Blender as above and reimport. Note the wheel bone names for step 7.
  4. Clean up the physics asset. Open the …_PhysicsAsset. Unreal gave every bone a collision body, including the wheels. Select the bodies on the four wheel bones and press Delete; keep only the one on the root (body) bone. The real wheels are the invisible ones from Wheel Setups (step 7); extra wheel bodies drag on the road and make the car spin or wobble. Save.
  5. Make it light for phones. Open the mesh: in Details → LOD Settings, set Number of LODs to 3 and click Apply Changes; if there's a Nanite section, untick Enable Nanite Support. Save.

No model yet? Unreal's free template sports car (Content Browser → Add → Add Feature or Content Pack → Blueprint → Vehicle) is fine for practice. It's built differently (a skeleton plus separate body and wheel meshes); the kit's README.md, section 3.5, walks through it.

7. Make the car drivable

Every car in the game is built on BP_VehiclePawnBase. It already handles driving, fuel, cameras, sounds, the wheel animation and multiplayer; you only say what your car looks like and how it drives.

  1. In your pack, create a folder Vehicles if it isn't there. In it: right-click → Blueprint Class → expand All Classes → search BP_VehiclePawnBase → Select → name it BP_RaviCar. Double-click to open it.
  2. The model. In Components (top left), select VehicleMesh. In Details, set Skeletal Mesh Asset to your mesh. Leave Anim Class as ABP_EvaVehicle: it spins and steers any car's wheels, so you don't make an animation Blueprint.
  3. The physics wheels. Select VehicleMovementComp. In Vehicle Setup → Wheel Setups, make four entries, with your wheel bone names:
    #Wheel ClassBone Name (example)
    0BPD_BaseWheel_FrontFL
    1BPD_BaseWheel_FrontFR
    2BPD_BaseWheel_RearRL
    3BPD_BaseWheel_RearRR
    These are what touch the road. The bone names must match the skeleton exactly (letter case too).
  4. Wheel size. The base wheels suit a small car. If yours are bigger or smaller, make your own: in Vehicles, right-click → Blueprint Class → All Classes → BPD_BaseWheel_Front → name it BPD_RaviCarWheel_Front; do the same from BPD_BaseWheel_Rear. In each, set Wheel Radius and Wheel Width (in cm, measured on your model) and, on the front one, Max Steer Angle. Use them in Wheel Setups.
  5. Make it drive like your car in VehicleMovementComp:
    • Mass (kg): a small car 1,100–1,400, an SUV 2,000.
    • Engine Setup → Max Torque (N·m) and Max RPM: more torque pulls harder; a small petrol car is around 200–300 N·m at 6,000 RPM.
    • Engine Setup → Torque Curve: if you edit it, keep every key linear (right-click a key → Linear). A curved key with a steep handle can swing below zero between keys, and the car then drives backwards when you accelerate.
    • Transmission Setup: gear ratios and when it shifts.
    • Differential Setup: front-, rear- or all-wheel drive.
  6. Only if your wheels are separate meshes (not part of the skeletal mesh): with VehicleMesh selected, Add → Static Mesh for each wheel, set its Static Mesh, and in Details → Sockets set Parent Socket to that wheel's bone, with Location 0, 0, 0. Turn right-hand wheels 180° around Z if their rims face inward.
  7. Optional: steering wheel settings and up to four animation buttons (doors, wipers) are on the VehicleAnimation component; see step 12.
  8. Compile and Save (top left).

Don't add any nodes to the Event Graph, functions or Construction Script. Components and changed values are fine; logic isn't allowed in packs, because phones can't load code from a pack. The kit rejects Blueprints with logic.

8. Put it in the garage

The garage finds cars through a small card called a vehicle definition.

  1. In RaviCars/Vehicles: right-click → Miscellaneous → Data Asset → EvaVehicleDefinition → name it DA_Vehicle_RaviCar. Open it.
  2. Fill in:
    FieldExampleNotes
    Vehicle Idravicars.ravicarPack name, a dot, the car; all lowercase, no spaces. Never change it once people use your pack: saves refer to it.
    Display NameRavi CarShown to players.
    DescriptionA family hatchback.Optional.
    AuthorRaviCredit for the car. (The Mods list shows the pack author you gave in step 4.)
    Pawn ClassBP_RaviCarYour Blueprint from step 7.
    Sort Order100100 or more, so the game's own cars come first.
  3. Save.

9. Add it to traffic

Traffic cars are driven by the game, so they only need a model. You can add the same car, or a different one.

  1. In RaviCars/Vehicles: right-click → Miscellaneous → Data Asset → EvaTrafficVehicleDefinition → name it DA_Traffic_RaviCar.
  2. Fill in:
    FieldExampleNotes
    Traffic Idravicars.ravicarSame rules as the Vehicle Id.
    Display NameRavi Car
    Meshyour skeletal meshThe same mesh as the drivable car works: its wheels roll if the bones have wheel names. Or set Static Mesh instead to a single mesh of the whole car (its wheels won't turn, which is hard to notice in traffic).
    Weight0.4How common it is. The game's own traffic cars are 1 each, so 0.2–0.5 mixes yours in.
    Min / Max Speed Factor0.9 / 1.1Cruising speed as a share of the speed limit.
    Mesh Yaw Offset0Set to 180 if the car drives backwards.
  3. Save.

Rolling wheels on traffic cars. For a skeletal mesh, the game finds the wheel bones by name (letter case doesn't matter) and spins them as the car drives:

A bone is a wheel ifExamples
its name contains wheel, tyre or tireWheel_FL, Phys_Wheel_BL, tyre_rear_left
its name is exactly a corner code: FL FR RL RR BL BR LF RF LR RB LBFL, rr, Bl (but not FL_Door)
never if the name contains steer, hub, suspension or brakeSteering, Hub_FL, BrakeDisc_FR

If a traffic car faces sideways or backwards on the road, fix it with Mesh Yaw Offset (90, -90 or 180): traffic doesn't use the car's physics setup, so the model's orientation is all that matters.

10. Test it in Unreal

  1. File → New Level → Basic. You get a floor to drive on.
  2. Drag BP_RaviCar from the Content Browser into the level, just above the floor.
  3. With it selected, in Details search Auto Possess and set Auto Possess Player to Player 0.
  4. Press Play (Alt+P). Check that the car sits on its wheels, doesn't sink or bounce, and drives forward. The game's touch controls only appear on the phone; here you're checking looks and physics. Press Esc to stop.
  5. Don't save this test level into your pack. Close it without saving, or save it outside the pack folder.

11. Check, build and install

  1. Check. In the Content Browser, right-click your pack folder → Validate Assets. Fix every error: usually something your pack uses that lives outside it (move it into the pack) or a Blueprint with logic. Warnings are advice: Nanite still on, a texture over 2048 px, a mesh over 30,000 vertices or without LODs.
  2. Save All and close Unreal.
  3. Build. In PowerShell in the kit folder (as in step 4): 
    powershell -ExecutionPolicy Bypass -File Tools/Mods/Build-VehiclePack.ps1 -Pack RaviCars
    It takes a few minutes. Hundreds of yellow Could not resolve package /Game/… warnings are normal: they're game files the kit doesn't include. Only red errors matter. The finished pack is in Plugins/GameFeatures/RaviCars/Saved/Package/RaviCars/: a RaviCars.uplugin file and Content/Paks/Android/ with three files.
  4. Copy it to your phone. Connect the phone by USB and choose File transfer on the phone. In File Explorer, open the phone and go to 
    Android/data/com.evastudios.vehiclesimulator/files/UnrealGame/VehicleSimulator/VehicleSimulator/Plugins/GameFeatures/
    (create Plugins and GameFeatures if they're missing, and open the game once first so the com.evastudios… folder exists). Copy the whole RaviCars folder there.
  5. Or let the build copy it: turn on USB debugging on the phone (Settings → About phone → Software information → tap Build number 7 times; then Settings → Developer options → USB debugging), install Android SDK Platform Tools so adb works, and add -Push to the build command. Use this if Windows can't show the Android/data folder on your phone.
  6. Or copy it with adb yourself (USB debugging on, run in PowerShell or cmd in the kit folder; from Git Bash, put MSYS_NO_PATHCONV=1 in front of each line):
    ToRun
    Create the packs folder (first time only)adb shell mkdir -p /sdcard/Android/data/com.evastudios.vehiclesimulator/files/UnrealGame/VehicleSimulator/VehicleSimulator/Plugins/GameFeatures
    Copy or update the packadb push Plugins/GameFeatures/RaviCars/Saved/Package/RaviCars /sdcard/Android/data/com.evastudios.vehiclesimulator/files/UnrealGame/VehicleSimulator/VehicleSimulator/Plugins/GameFeatures/
    List installed packsadb shell ls /sdcard/Android/data/com.evastudios.vehiclesimulator/files/UnrealGame/VehicleSimulator/VehicleSimulator/Plugins/GameFeatures
    Remove a packadb shell rm -r /sdcard/Android/data/com.evastudios.vehiclesimulator/files/UnrealGame/VehicleSimulator/VehicleSimulator/Plugins/GameFeatures/RaviCars
    Restart the gameadb shell am force-stop com.evastudios.vehiclesimulator
    If adb isn't found, use its full path: %LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe. After renaming or deleting assets in the pack, remove the old folder before pushing the new one, so no stale files are left.
  7. Close the game completely (swipe it away from recent apps) and open it again.
  8. On the main menu tap Mods. Your pack should say Loaded and list Vehicles: Ravi Car and Traffic: Ravi Car. If it says Could not load, the reason is underneath; see Troubleshooting.
  9. Go to the garage: your car comes after the game's own. Drive it, and watch for it in traffic.

To update your pack, change it in Unreal, build again, and copy the new folder over the old one. To share it, zip the RaviCars folder from Saved/Package; players install it as described in Install a vehicle pack.

12. Animation: steering wheel, buttons and custom animations

You don't need to make an animation Blueprint. Every car made from BP_VehiclePawnBase uses the game's ABP_EvaVehicle, which works on any skeleton: it spins and steers the wheel bones in your Wheel Setups and turns the steering wheel. Everything below is set on the car's VehicleAnimation component (select it in your vehicle Blueprint's Components panel).

Needs the current mod kit: if /Game/Blueprints/VehicleBP in your kit has no ABP_EvaVehicle, download the kit again.

A steering wheel that turns

  1. In your 3D model, give the steering wheel its own bone named exactly SteeringWheel, with the steering-wheel geometry skinned to it.
  2. On the VehicleAnimation component: Steering Wheel Angle = how far it turns at full lock, in degrees (default 90; a negative number turns it the other way). Steering Wheel Axis = Roll, Pitch or Yaw, the axis the bone turns around. Try Roll first; if the wheel tilts instead of turning, try the others.

Buttons for your own animations (doors, wipers, a lift...). The driving screen has four buttons. On the VehicleAnimation component, fill in Actions; the four slots are the four buttons in order:

  • Name: the button's label. Leave it empty and that button is hidden.
  • Mode: Toggle (each press switches it on or off) or Hold (on while the button is held).
  • Blend Time: seconds the animation takes to go from closed to open.

Other players in a multiplayer game see your actions too.

Making the animation: an Extras Blueprint. It adds your animation on top of ABP_EvaVehicle, so the wheels and steering wheel keep working. It's the one kind of Blueprint in a pack that may contain nodes.

  1. In your pack, right-click → Animation → Animation Blueprint. In the dialog: Parent Class = EvaVehicleAnimInstance (search for it; it's a C++ class; don't pick ABP_EvaVehicle, a child of it can't change its animation). Skeleton = your car's skeleton. Name it ABP_<Car>_Extras.
  2. Open it. Click Class Settings in the toolbar. In Details → Interfaces → Implemented Interfaces, click Add → ALI_EvaVehicleExtras. Under My Blueprint → Animation Layers a layer called Extras appears. Double-click it: it has an Input Pose connected to an Output Pose.
  3. Build between them. For example, a door on button 1: 
    Input Pose → Local To Component → Transform (Modify) Bone → Component To Local → Output Pose
    Right-click an empty spot and search each node's name to add it; drag between the pose pins to connect.
  4. Select Transform (Modify) Bone. In Details: Bone to Modify = the door bone; Rotation Mode = Add to Existing; Rotation Space = Bone Space. Type how far it opens on the node's Rotation pin in the graph (e.g. Yaw 70). While a pin is shown on the node, its value is used and the same field in Details is ignored.
  5. Right-click → search Get Action 1 Alpha → connect it to the node's Alpha pin. It goes from 0 (closed) to 1 (open) over the Blend Time when button 1 is pressed. Buttons 2–4 are Action 2..4 Alpha.
  6. Compile and Save. In your vehicle Blueprint, select VehicleAnimation and set Extras Anim Class to this Blueprint. Leave VehicleMesh's Anim Class as ABP_EvaVehicle.

Other values you can use in the Extras graph (right-click → search the name): Speed (km/h), Throttle, Brake, Steering (-1 to 1), Gear, Engine RPM, Handbrake, Is Reversing, Is Player Driving, and Action 1..4 (on/off). For example, a speedometer needle is a Transform (Modify) Bone whose rotation comes from Speed.

More examples. Several parts can move in one Extras layer: chain one Transform (Modify) Bone per part between Local To Component and Component To Local.

13. Troubleshooting

ProblemFix
Unreal says the kit's modules are missing or built for another engineInstall exactly Unreal Engine 5.8.
The pack isn't active in Unreal / its cars don't showRestart Unreal after creating the GameFeatureData (step 5). Check its name matches the pack exactly.
Build error: Uncooked … content … is being referenced by DLC!Your pack uses something outside the pack. Validate Assets lists it; move it into the pack.
Hundreds of Could not resolve package warnings, or warnings about missing /Game/SoundsNormal. Only errors matter.
Mods says Could not loadRead the reason under it. Usually the pack was built with a kit for another game version, or copied to the wrong folder (the .uplugin must be directly inside GameFeatures/RaviCars/).
Car not in the garageThe definition isn't in /RaviCars/Vehicles, Pawn Class is empty, or the GameFeatureData is missing the EvaVehicle entry.
Car floats, sinks or flipsWheel Bone Names don't match the skeleton, wrong wheel radius, or the model's pivot isn't at ground level.
Wheels don't turnVehicleMesh's Anim Class isn't ABP_EvaVehicle (or an animation Blueprint for your skeleton), or the Bone Names in Wheel Setups are wrong.
Steering wheel doesn't turn, or turns the wrong wayThe bone must be named exactly SteeringWheel. Change Steering Wheel Angle (negative) or Steering Wheel Axis on VehicleAnimation (step 12).
A button is missingThat slot's Name is empty in VehicleAnimation's Actions.
Button works but nothing movesThe Extras Blueprint must implement ALI_EvaVehicleExtras and be set as Extras Anim Class; Anim Class must stay ABP_EvaVehicle. Type the amount on the node's pin, connect Action N Alpha to Alpha, and compile after every change.
Wheel meshes float away from the carThe wheel component isn't under VehicleMesh, Parent Socket is wrong, or its Location isn't 0, 0, 0.
Car drives backwards when acceleratingThe Torque Curve dips below zero: make its keys linear (step 7).
Car spins in place when accelerating (one way forward, the other in reverse)The root bone is rotated (it must read 0, 0, 0), or the physics asset still has bodies on the wheel bones. See step 6.
Traffic car drives backwardsSet Mesh Yaw Offset to 180.
Can't see Android/data on the phone from WindowsUse USB debugging and -Push (step 11).

Get the Mod Kit

Download the Mod Kit

A small zip (about 1 MB) on Google Drive. Unzip it on your PC, keep the folder name VehicleSimulator, and start with the README.md inside.

What you get:

  • A cut-down copy of the game's Unreal project with what a vehicle needs to plug into the game, and no more. It contains no car models and no sounds: bring your own model; in the game your car uses the game's engine and crash sounds.
  • Scripts to create, check, build and install packs.
  • The full modding guide, from importing a model to troubleshooting.

Packs need a version of the game with the Mods button on the main menu. Each kit is made for one version of the game (see MODKIT_RELEASE.txt in the kit); when the game updates, download the new kit and rebuild your pack.

Rules

  1. Only content you have the rights to. No models or textures taken from other games.
  2. Everything in the pack. A pack may use its own files and what the game ships; nothing else.
  3. No scripts. Blueprints may add components and change values, but not add logic. Phones can't load code from a pack.
  4. Ids start with your pack name, lowercase: <pack>.<vehicle>. Never change an id once people use the pack; saves refer to it.
